# Sunshine Client 0.1.0-rc.10

This usability repair release fixes the first-run setup path:

- Setup now checks the real nested `pairing.state` postcondition, so a successful enrollment is no longer reported as failed.
- Installer-only elevation flags are filtered before invoking `pair`, and setup stops an accidentally running service before taking the provisioning maintenance lock.
- The Windows MSI installs and registers the stopped service without launching an interactive wizard inside the installer transaction. Run `sunshine-client setup` from an Administrator terminal afterward.
- A missing first Manager acknowledgement is reported as a connection warning after configuration, pairing, and service startup have succeeded; it no longer rewrites the whole setup result as failure.

Sunshine `2026.516.143833` and the current stable `2026.906.222525` are accepted. The Client reports the exact observed Sunshine version to the Manager, which must run Server 0.10.5 or later. Unverified prerelease versions remain rejected.

The Client now consumes Foundation Client 0.8.0, including explicit TLS trust modes, public/private address separation, bounded recovery polling, and native secure-HTTP CI coverage. Packages remain unsigned prerelease artifacts.
